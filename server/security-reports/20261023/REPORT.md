## Audit and reachability

Both the initial successful registry audit and final audit returned zero findings across all severities. The previously reported nine could not be reproduced in this active directory; do not describe them as nine vulnerabilities fixed during this pass. There were temporary registry/DNS failures; the saved final audit is a subsequent successful response. Installed tree snapshots accompany the lockfile audit. Verify the directory/lockfile if another terminal still reports nine.

* proxy-addr@2.0.8 was already installed. The upstream critical IPv4-mapped IPv6 trust-subnet advisory affects versions below 2.0.8. This configuration accepts only false or loopback, not arbitrary trust subnets. Direct-peer/header spoof tests and loopback address tests passed. Live reverse-proxy topology and header overwriting were not tested on Azure. Local malicious processes remain within the loopback trust boundary.
* path-to-regexp@8.4.2 was already installed under router@2.2.0. Express routes and parsing remain externally reachable, but the current audit identifies no affected version. This is not proof of immunity to every routing or resource-exhaustion problem.
* brace-expansion@2.1.7 was already installed through archive/glob helpers. Backup archive paths are generated by server code, not exposed as arbitrary public glob inputs. No finding remains in the audited tree.
* mysql2 was reachable through application database queries. Current and updated trees have no reported advisory. The application uses parameterized statements in reviewed authentication/session paths; this limited review is not a comprehensive SQL-injection audit. Production configuration requires a non-root account and loopback database; local development retains root/empty-password defaults when configuration is absent. Do not use these defaults for production. No remote database TLS claim is made.
* Nodemailer supports account notifications/password recovery. Reviewed helper validates addresses/from headers, disables file and URL attachment access, uses bounded timeouts, and requires STARTTLS on explicit SMTP_HOST port 587 (implicit TLS on 465). Service-based transport behavior depends on provider configuration. No new credentials were read into reports or changed.
* JWT verification pins HS256, checks account status, password version, session epochs and revocation. Existing tests cover forged/expired tokens, role/barangay separation, reset-code hashing/single use, throttling and session invalidation. No claim of exhaustive authentication review is made.
* Production configuration restricts origin and proxy trust; development without PUBLIC_ORIGIN allows permissive CORS and defaults to listening on all interfaces. Use a trusted development network or explicit loopback binding. These pre-existing settings were not silently changed.
