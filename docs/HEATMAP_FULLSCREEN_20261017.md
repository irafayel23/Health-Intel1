# Heatmap fullscreen and workflow rehearsal — 17 October 2026

BHW and MHO heatmaps share a Fullscreen button. It expands the existing map over the browser viewport and keeps its zoom, selected barangay and layers. Exit fullscreen or Escape returns it to the original position. A height-preserving placeholder prevents the portal from collapsing while the map is expanded. Keyboard focus stays inside the expanded map, background content becomes inert, and existing accessibility attributes and focus are restored on exit. Light and dark styles use the existing shared stylesheet. No new dependency, database field or API is required.

The disposable-database rehearsal creates a BHW disease case with an initial return plan, records an MHO follow-up against the same case with a later return date, then records a BHW admission without another dated plan. Both roles see the same pending plan and visit history. The last step removes pending tracking while retaining all historical advice. The original disease case is unchanged and no extra resident or case is created.

Validation: all 187 regression tests passed after browser verification exposed and fixed a fullscreen breakpoint interaction with portal navigation. Thirteen focused map/navigation tests also passed. These cover both map IDs, Escape, focus wrapping, repeated toggles, background inert-state restoration across breakpoints, page exit, disease aggregation, unknown/missing breakdown data, empty states and escaped text. Integration fixtures remove their temporary databases and verify the original database remains unchanged.

## Map-details implementation

The shared renderer now keeps the barangay heading and a 44px Close button outside the scrollable body. A 420px panel docks to the right on larger maps and becomes a bottom sheet when the visible map width is narrow. The content shows the active total, three severity cards, a proportional severity strip, one disease table with totals, a short color explanation and a refresh footer. Light/dark styles preserve the existing green/orange/red severity colors; purple represents incomplete severity. No patient-level fields are added.

Disease rows combine counts across severities and sort by total descending. Unknown severity adds an explicit column and notice. If an older API omits disease details, an explicitly labeled unavailable-breakdown row preserves those counts without inventing a disease. Classification-review warnings remain visible. Color explanations continue to use the server's recorded-severity rules, and the panel states that these are not disease ratings or outbreak boundaries.

Keyboard activation moves focus to Close; closing returns it to the originating map marker without reopening the panel. Keyboard scrolling inside the summary does not pan the map. Refresh retains a pinned barangay and its content scroll position. Portal navigation now respects fullscreen isolation when changing responsive breakpoints and restores the appropriate sidebar state on exit. No database or API change was required.
